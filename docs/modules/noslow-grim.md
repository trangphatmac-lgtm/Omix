# NoSlowDown Grim 模式

在 NoSlowDown 的 `Mode` 中选择 `Grim` 并开启模块。默认模式仍为 `Vanilla`，现有配置继续有效；`Keep Sprint` 在 Grim 成功进入取消减速阶段时保持疾跑，关闭时保留原版物品使用的疾跑限制。

## 使用范围

- 食物（含 FOOD 组件）和饮用药水：使用包前发送主副手交换动作，再以相反的手重发使用包，保留原包的 sequence、yaw、pitch。本地不交换物品栏。
- 弓、未蓄能弩：进入使用阶段并缓冲接收包，保留原使用包，不换手。
- 双手均为食物/饮用药水、已蓄能弩、不支持的物品、非 MISS 准星下的交互不启用特殊使用流程。盾牌、望远镜、三叉戟不在支持范围内。
- 活动期间锁定开始使用时的快捷栏槽位，数字键和滚轮不切槽。实际使用入口先完成原版选槽同步，再进入准备阶段，避免新选槽尚未发给服务器就被锁定。
- 背包点击后的同一玩家 tick 不开始新的特殊使用。主动点击背包、方块交互和手动交换/丢弃等动作会先退出当前流程；取消减速不会覆盖这些操作。

## 状态与恢复

状态机、Minecraft 适配、发包处理与接收队列全部集成在 `src/main/java/cn/omix/module/impl/move/NoSlowDown.java` 中，状态机作为模块的静态内部类保留独立测试能力，不再拆分 Controller 或 State 源文件。对应测试位于 `src/test/java/cn/omix/module/impl/move/GrimNoSlowStateTest.java`。

| 事件 | 状态变化 |
| --- | --- |
| 合格物品的使用入口 | NONE → PREPARING |
| 合格的使用包 | PREPARING/NONE → USING |
| 发送 RELEASE_USE_ITEM | USING → WAIT_RELEASE_BOUNDARY，并立即停止取消减速 |
| 已换手情况下松手后的第一个移动包 | WAIT_RELEASE_BOUNDARY → WAIT_RESTORE_MOVEMENT |
| 第二个移动包 | 交换回来，进入 FINISH_AFTER_MOVEMENT |
| 本地自然结束 | 有换手则 WAIT_RESTORE_MOVEMENT，否则 WAIT_STOP_MOVEMENT |
| 未换手的松手/自然结束 | 下一移动边界进入 FINISH_AFTER_MOVEMENT |
| 下一客户端 PRE tick | 清状态、释放槽位、回放接收队列 |

没有移动包时，等待阶段以玩家 age 兜底：首次记录等待年龄，差值严格大于 2 才推进一次；真实移动包推进不重置该年龄。连续食用可以继承尚未恢复的换手状态。继承后若准备过期或后续使用被拒绝，会主动恢复换手，避免遗失交换状态。

禁用和切出 Grim 时恢复当前会话。世界、连接或玩家对象变化时丢弃旧队列和状态，不向新会话回放旧物品栏、位置或实体更新。状态为实例字段，不在模块/会话之间共享。

## 接收包与项目适配

基于用户提供的 `NoSlow-逆向分析交付.zip` 中 `NoSlowReadable.java` 和分析报告实现；附件中的复现命令不是本项目的构建指令。

接收策略保留模型中的白名单：实体相对移动、位置同步和状态包放行；实体绝对位置包仅缓冲末影珍珠；实体追踪和速度包仅缓冲本玩家；其他业务包进入 FIFO 队列。

本项目的 `PacketEvent.Received` 发生在网络线程。新增 `PacketApplyBatcher.Entry` Mixin 在客户端主线程、包实际应用前执行 Grim 缓冲，避免在网络线程修改状态、查询实体或回放包。其他模块先前取消的接收包不会进入此队列。

与原客户端外部设施的适配差异：

- 没有原客户端 CRITICAL 优先级槽位仲裁器；通过原版选槽同步入口和输入拦截实现本模块锁定。
- 没有原客户端多 owner 接收队列；本模块自行持有 FIFO。同会话清除所有权时回放有效更新，避免连续使用丢失服务端更新；换世界时直接丢弃。主动中止且已换手时，先恢复交换，再回放并过滤旧 `SetPlayerInventoryS2CPacket` / `ScreenHandlerSlotUpdateS2CPacket`。
- KeepAlive、CommonPing、断线、重生、加入游戏和协议状态切换不参与长时间缓冲。队列达到 4096 包时退出当前流程并回放，避免持续使用导致无界增长。
- Scaffold 开启、AutoBlockIn 接管鼠标、NoFall Grim 控制窗口、玩家死亡/旁观/骑乘，以及主手水桶下落超过 3 格时退出或暂停特殊流程。活动状态下主手末影珍珠也退出。
- 原样本专用的 Stuck、Helper、AntiWeb、外部 use guard 和 ViaFabricPlus 协议查询没有在本项目中直接对应的服务，不引入空实现或新增这些模块。本实现面向项目原生 Minecraft 1.21.11 协议；不保证经协议转换连接旧版本服务端的行为。

## 验证与边界

JUnit 状态机测试覆盖主副手改写、参数保留、物品排除、弓弩路径、两次移动边界、自然结束、严格超时、连续使用、槽位锁定、背包点击保护、包白名单、恢复顺序和实例隔离。编译验证包含新增的 Mixin 与 Minecraft 1.21.11 API 适配。

附件中的 1081 项差分结果验证的是附件模型；本项目测试单独验证移植后的状态逻辑。尚未进行真实 Grim 服务端联机验证，模式名称不代表对任意 Grim 版本的绕过保证。

建议联机回归：分别测试主手/副手食物、药水、弓弩、提前松手、自然吃完、长按连续食用、静止使用、双手食物、点方块、数字键/滚轮、背包点击、切换模式、禁用、重生和换世界；确认移动、物品数量和最终手持物品恢复正常。
