# NoSlowDown Grim 模式

在 NoSlowDown 的 `Mode` 中选择 `Grim` 并开启模块。默认仍为 `Vanilla`。`Keep Sprint` 仅在 Grim 的取消减速阶段保持疾跑，关闭时保留原版物品使用的疾跑限制。

## 使用范围

- 食物（含 FOOD 组件）、饮用药水、弓和未蓄能弩：保留原使用包的 hand、sequence、yaw、pitch。主手和副手都在原来的手中完成使用，不额外发送主副手交换动作。
- 双手均为食物/饮用药水、已蓄能弩、不支持的物品、非 MISS 准星下的交互不启用特殊使用流程。盾牌、望远镜、三叉戟不在支持范围内。
- 开始使用后，收到本玩家、与本次使用手匹配的活动使用元数据之前保留原版减速；收到后才解除减速及使用物品造成的疾跑阻止。另一只手的使用标志不会开启本次取消减速。
- 活动期间锁定开始使用时的快捷栏槽位，数字键和滚轮不切槽。原版选槽同步先完成，再进入准备阶段。
- 背包点击后的同一玩家 tick 不开始特殊使用。背包点击、方块交互、手动换手/丢弃等操作会先结束当前缓冲流程。

## 主副手进食与物品栏同步修复

本版本保留逆向模型的接收缓冲、槽位锁定和移动边界恢复，但将食物、药水也接入弓箭使用的原手确认流程。

旧的主手进食会先将金苹果交换到服务端副手，再重发副手使用包。用户提供的 Grim 源码 `PacketEntityReplication` 会在 `SET_SLOT` / `WINDOW_ITEMS` 的事务确认回调中检查使用手的物品类型变化，并可能调用 `resetItemUsage`。这与开始使用时放行前置 Ping 的逻辑冲突：确认换手槽位变化时，服务端进食可能被提前清除。保留原手使用后，不再制造这一轮槽位变化，正常消费仍由服务端完成。

接收队列完整保留 `SetPlayerInventoryS2CPacket`、`ScreenHandlerSlotUpdateS2CPacket` 和 `InventoryS2CPacket`，按到达顺序逐个回放。完整背包同步不能越过较旧的单槽更新；自然结束、提前松手和中止时都不再过滤单槽包，包括最后移动边界之后、回放之前到达的更新。消耗数量、最后一颗变为空槽、药水容器和其他背包变化均以服务端更新为准，不手动交换本地物品或猜测消耗数量。

## 连续食用与结束

长按右键吃完一颗金苹果后，保留真实的按键状态，不调用 `useKey.setPressed(false)`。Minecraft 1.21.11 客户端的使用计时归零并不会自行完成消耗；必须放行服务端的 `EntityStatusS2CPacket`（`CONSUME_ITEM`，状态码 9），由原版完成本地消耗和结束动画。不会通过本地计时伪造物品消耗或药水效果。

每次使用完整走完恢复流程，再允许原版以仍按住的右键开始下一颗。恢复中的新使用返回 PASS，直接发送的重复使用包也会被阻止，防止新一轮清空尚未回放的确认或物品栏更新。根据是否移动，恢复可能等待少量 tick，无需松开再按右键。

| 事件 | 状态变化 |
| --- | --- |
| 合格物品的使用入口 | NONE → PREPARING |
| 合格的原手使用包 | PREPARING/NONE → USING |
| 发送 RELEASE_USE_ITEM | USING → WAIT_RELEASE_BOUNDARY，立即停止取消减速 |
| 服务端消费状态令本地自然结束 | USING → WAIT_STOP_MOVEMENT，不改使用键 |
| 松手/自然结束后的下一移动包 | 进入 FINISH_AFTER_MOVEMENT |
| 下一客户端 PRE tick | 清状态、释放槽位、完整回放接收队列，然后可以再次使用 |

没有移动包时，首次记录等待年龄，玩家 age 差值严格大于 2 才推进。禁用和切出 Grim 会回放当前会话。世界、连接或玩家对象变化时丢弃旧队列，不向新会话回放旧更新。接收队列上限为 4096 包，达到上限会退出特殊流程并回放。

## 接收确认顺序

实现参考 `NoSlow-逆向分析交付.zip` 的业务模型和 `supporting-evidence/llli11lliiii.java.txt` 中共享队列的 `liilllllllll` 排除规则，并针对本项目调整使用确认和背包同步顺序。

- 实体相对移动、位置同步、实体状态包放行；实体绝对位置包仅缓冲末影珍珠；实体追踪和速度包仅缓冲本玩家。
- KeepAlive、位置纠正、交互序列确认、生命/饥饿同步、实体生成/销毁/装备、区块、聊天、音效、记分板等放行。完整背包同步与单槽更新一起缓冲。
- `CommonPing` 与 KeepAlive 不同。根据 Grim 的 `PacketSelfMetadataListener`、`PacketPingListener`，使用元数据前的事务确认解除确定使用状态，后一个确认重新确认使用状态。本次匹配的使用元数据到达之前放行 Ping，期间保留原版减速；元数据到达后，后续 Ping 与该元数据一起排队，防止 Pong 越过尚未应用的使用状态。恢复时 FIFO 回放，每个确认包仅回复一次。
- `PlayerPositionLookS2CPacket` 到达时立即中止当前流程，并交给原版应用及确认，避免位置纠正积压至松手后回放。
- 断线、重生、加入游戏和协议状态切换不缓冲。清队列不应用包或发送回复；只有显式回放才发送相应回复，回放逐包检查仍处于原会话。

接收拦截位于 `PacketApplyBatcher.Entry` 的客户端主线程、包实际应用之前。网络线程中已被其他模块取消的包不会进入此队列。使用状态字段 ID 通过 `LivingEntityAccessor` 读取，不硬编码运行时追踪字段序号。

## 代码与兼容边界

Minecraft 适配由 `src/main/java/cn/omix/module/impl/move/NoSlowDown.java` 承接。按仓库 AGENTS.md 约定，状态机、包策略与队列位于 `src/main/java/cn/omix/util/player/noslow/`，相应测试位于 `src/test/java/cn/omix/util/player/noslow/`。

项目没有原客户端 CRITICAL 槽位仲裁器、多 owner 队列、Stuck、Helper、AntiWeb、外部 use guard 和 ViaFabricPlus 协议查询服务。槽位通过原版同步入口及输入拦截锁定；Scaffold、AutoBlockIn 鼠标接管、NoFall Grim 控制窗口、死亡/旁观/骑乘、主手水桶下落超过 3 格等条件会阻止特殊流程。实现面向项目原生 Minecraft 1.21.11 协议，并非原客户端完整运行环境的逐包复刻。

## 验证

状态机测试覆盖主副手保持原使用包、物品资格、松手与自然结束、移动边界/静止超时、主副手保持右键连续使用、恢复阶段重复使用、中止及实例隔离。包策略测试使用实际 Minecraft 包类型，覆盖 Ping → 匹配使用元数据 → Ping 顺序、错误手/不同玩家/无关字段、状态码 9、位置纠正与交互确认、一次性 FIFO 回放及会话切换丢弃。

背包分类测试使用三种实际 Minecraft 背包包的类，确认完整快照和两种单槽更新都进入缓冲流程；回放顺序及仅应用一次由生产队列测试覆盖。测试不启动物品注册表、真实服务端或反作弊运行环境，尚不覆盖原版背包处理器实际应用物品栈；金苹果数量、效果和两手位置仍需联机验证。

附件的 1081 项差分结果仅验证附件模型。编译及自动化测试通过不等于已完成真实服务端联机验证。联机回归重点：主副手移动和静止时长按连续吃两颗金苹果，确认每颗实际消耗并获得效果，吃到最后一颗后两手位置仍一致；药水容器；拉弓后松手射箭；提前松手；切换模式；服务器主动传送；无积压回放引发的额外位置纠正与 VL。
